Current Code Verification

Current code now matches this USER_ADMIN permission requirement.

Reason:
The copy API now passes Authentication roles to the service and checks edit permission.

Current copy controller:

POST /facilities/{facilityId}/copy

passes:

extractRoleNames(authentication)

Current copy service:

copyFacility(Long facilityId, Map<String, Object> request, Set<String> userRoles)

calls:

ensureEditPermission(facilityId, userRoles)

Therefore:
1. SYS_ADMIN can copy.
2. USER_ADMIN can copy only when permission_id = 10 exists for the request facility_id and one of the user's roles.
3. USER_ADMIN without permission_id = 10 should get permission_denied.

Before Testing: Permission DB Setup And Facility ID Finder

Purpose:
For USER_ADMIN copy, the request path facility_id must have permission_id = 10
for one role contained in the USER_ADMIN access token.

Use this section before every USER_ADMIN success test.

Step 1: Decide the role name used by the token.

Example:
If your USER_ADMIN token contains role R_USER01, use:

<USER_ADMIN_ROLE> = R_USER01

If your token contains role USER_ADMIN, use:

<USER_ADMIN_ROLE> = USER_ADMIN

Important:
Use the exact role value that appears in the JWT after backend role extraction.
In many local tests this is:

R_USER01


Step 2: Make sure permission_master has permission_id = 10.

SQL:

INSERT INTO permission_master (
  permission_id,
  permission_name,
  created_at,
  updated_at,
  deleted_at
)
VALUES (
  10,
  '施設編集',
  CURRENT_TIMESTAMP,
  CURRENT_TIMESTAMP,
  NULL
)
ON CONFLICT (permission_id) DO UPDATE
SET permission_name = EXCLUDED.permission_name,
    updated_at = CURRENT_TIMESTAMP,
    deleted_at = NULL;


Step 3: Find facilities that already have USER_ADMIN edit permission.

Replace:
<USER_ADMIN_ROLE> with the token role, for example R_USER01.

Current backend note:
For permission checks, the current Java code compares the token role with
facility_role_permission.keycloak_role_id.
Therefore, a row with only keycloak_role_name is not enough for USER_ADMIN copy success.

SQL:

SELECT
  ft.facility_id,
  ft.parent_id,
  ft.facility_name,
  frp.permission_id,
  frp.keycloak_role_id,
  frp.keycloak_role_name
FROM facilities_tree ft
JOIN facility_role_permission frp
  ON frp.facility_id = ft.facility_id
 AND frp.permission_id = 10
 AND frp.keycloak_role_id IN ('<USER_ADMIN_ROLE>')
 AND frp.deleted_at IS NULL
WHERE ft.deleted_at IS NULL
ORDER BY ft.facility_id;

If this returns rows:
Use one returned facility_id as <request_facility_id>.

If this returns 0 rows:
Run Step 4 to create permission data.
