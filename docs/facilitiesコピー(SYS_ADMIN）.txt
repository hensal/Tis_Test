facilitiesコピー(SYS_ADMIN） Postman Test Steps

Source Excel sheet:
APIテスト仕様書(facilities).xlsx
Sheet: facilitiesコピー(SYS_ADMIN）

Important endpoint note:
The Excel title says:
POST /facilities/{facilityid}/move

But this is the copy test sheet. In the current backend and facilities.md,
the copy API endpoint is:

POST /facilities/{facilityId}/copy

Use /copy for Postman copy testing.

Current implementation notes:
These docs describe the Excel expected behavior. Some later Excel checks may reveal current backend gaps:

1. FILES rows:
   Excel expects new FILES rows for copied facility_images/maps.
   Current code copies facility_images/maps rows with the same file_id, so new FILES rows may not be created.

2. Physical files:
   Excel expects physical/S3 files to be copied.
   Current code appears to copy DB rows only.

3. annotations:
   Excel expects annotations not to be copied.
   Current code currently copies annotations for the selected source facility.

4. Children/descendants:
   Excel expects children and descendants to be copied recursively.
   Current code currently copies only the selected source facility's direct related rows.

Use the Postman and SQL steps below to confirm each behavior on the target computer.


Common Postman Setup

Base URL:
http://localhost:8081

Portable setup for any computer:
If the backend runs on another host or port, replace http://localhost:8081 with that computer's backend URL.

Examples:
http://localhost:8081/facilities/<facilityId>/copy
http://192.168.1.20:8081/facilities/<facilityId>/copy

Do not hardcode facility IDs from one computer.
Always run the SQL in this document on the target computer's DB first, then replace placeholders like:
<valid_facility_id>
<valid_parent_id>
<valid_target_facility_id>
<response_facility_id>

Method:
POST

Endpoint format:
{{baseUrl}}/facilities/{{facilityId}}/copy

Headers:
Authorization: Bearer <SYS_ADMIN_ACCESS_TOKEN>
Content-Type: application/json

Normal request body format:
{
  "parent_id": <parent_id>,
  "target_facility_id": <target_facility_id_or_null>
}

target_facility_id rule:
You cannot use any random target_facility_id from the DB.
If target_facility_id is not NULL, it must be a facility directly under the same parent_id.

Example:
{
  "parent_id": 1110,
  "target_facility_id": 1111
}

This is valid only if facility_id 1111 has parent_id 1110.

Check with SQL:

SELECT COUNT(*)
FROM facilities_tree
WHERE facility_id = 1111
  AND parent_id = 1110
  AND deleted_at IS NULL;

If count = 1, the combination is valid.
If count = 0, the API should return an error.

If you want to copy to the first position under parent_id 1110, use:
{
  "parent_id": 1110,
  "target_facility_id": null
}

Case 1-1-4: Refresh token sent as bearer token

Purpose:
Excel says a correct refresh token is sent.
For this Spring Security resource-server API, Authorization should normally use an access token.
If you send a refresh token as Bearer token, the expected practical result is usually invalid_token.

Exact endpoint to write in Postman:
http://localhost:8081/facilities/<valid_facility_id>/copy

Method:
POST

Headers:
Authorization: Bearer <SYS_ADMIN_REFRESH_TOKEN>
Content-Type: application/json

Body:
{
  "parent_id": <valid_parent_id>,
  "target_facility_id": null
}

Expected by Excel:
Normal facility information is returned.

Expected by current backend behavior:
{
  "success": false,
  "error_code": "invalid_token",
  "message": "認証情報が不正です",
  "errors": null,
  "data": null
}

Current backend note:
If this returns invalid_token, the current code is behaving as a normal OAuth2 resource server.
Refresh tokens are usually used only with Keycloak token refresh endpoint, not as API bearer tokens.

Case 1-2: Request parameters - copy to first position

Excel title:
リクエストパラメータ
（先頭へのコピー）
（コピー元データがFULLで紐づくデータがある場合）

Purpose:
Copy a facility that has full related data, and place the copied facility at the first position under a different parent.

Condition:
1. Use a source facility that has related data.
2. parent_id must be different from the source facility's current parent_id.
3. target_facility_id must be NULL.

Find a source facility with related data:

SELECT
  ft.facility_id,
  ft.parent_id,
  ft.facility_name,
  COUNT(DISTINCT fi.image_id) AS image_count,
  COUNT(DISTINCT m.map_id) AS map_count,
  COUNT(DISTINCT mp.map_point_id) AS map_point_count,
  COUNT(DISTINCT frp.facility_role_permission_id) AS role_count,
  COUNT(DISTINCT e.equipment_id) AS equipment_count
FROM facilities_tree ft
LEFT JOIN facility_images fi
  ON fi.facility_id = ft.facility_id
 AND fi.deleted_at IS NULL
LEFT JOIN maps m
  ON m.facility_id = ft.facility_id
 AND m.deleted_at IS NULL
LEFT JOIN map_points mp
  ON mp.facility_id = ft.facility_id
 AND mp.deleted_at IS NULL
LEFT JOIN facility_role_permission frp
  ON frp.facility_id = ft.facility_id
 AND frp.deleted_at IS NULL
LEFT JOIN equipments e
  ON e.facility_id = ft.facility_id
 AND e.deleted_at IS NULL
WHERE ft.deleted_at IS NULL
GROUP BY ft.facility_id, ft.parent_id, ft.facility_name
HAVING COUNT(DISTINCT fi.image_id) > 0
    OR COUNT(DISTINCT m.map_id) > 0
    OR COUNT(DISTINCT mp.map_point_id) > 0
    OR COUNT(DISTINCT frp.facility_role_permission_id) > 0
    OR COUNT(DISTINCT e.equipment_id) > 0
ORDER BY ft.facility_id;

Use one returned facility_id as:
<full_source_facility_id>

Use its parent_id as:
<source_current_parent_id>

Find a different destination parent:

SELECT facility_id, parent_id, facility_name
FROM facilities_tree
WHERE deleted_at IS NULL
  AND facility_id <> <source_current_parent_id>
ORDER BY facility_id;

Use one returned facility_id as:
<different_parent_id>
